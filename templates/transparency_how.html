{# Overview #}
ภาพรวม: ทำไมต้องมีระบบจัดสรรที่โปร่งใส?
ระบบเดิมที่ "ใครจ่ายก่อนได้ก่อน" สร้างความไม่เป็นธรรมให้ผู้ค้ารายย่อยที่ไม่มีเวลาหน้าจอ Smart Hawker ใช้ สูตรคะแนน (Scoring) และ สลากตรวจสอบได้ (Verifiable Lottery) ในการตัดสินใจแทน โดยเน้น 3 มิติ ได้แก่ ความยาวนานการรอคิว, การหมุนเวียนพื้นที่, และ โควตาผู้ค้ารายย่อย
{# Scoring Formula #}
สูตรคะแนน (Scoring Formula)
score = W_WAIT × days_waiting
+ W_ROTATION × rotation_bonus
+ W_QUOTA × quota_bonus

W_WAIT = 0.5 (50%)
W_ROTATION = 0.3 (30%)
W_QUOTA = 0.2 (20%)

{# Lottery Mode #}
โหมดสลาก (Verifiable Lottery)
เมื่อผู้สมัครมีคะแนนเท่ากัน หรือ admin เลือกใช้ โหมดสลากจะถูกใช้แทน Scoring
seed_input = lot_id + ":" + date_str + ":" + public_salt
seed = SHA256(seed_input).hexdigest()

# ใช้ seed ในการสับลำดับรายชื่อผู้สมัคร
random.Random(seed).shuffle(applicants)

# ผู้อยู่อันดับ 1 หลังสับ = ผู้ได้รับการจัดสรร
ทำไม Verifiable ได้?
  • seed สาธารณะ — บันทึกลง allocation_record ทุกครั้ง ทุกคนดูได้
  • reproducible — ใส่ seed เดิม + รายชื่อเดิม → ได้ผลเหมือนกันทุกครั้ง 100%
  • ตรวจสอบเองได้ — python -c "import hashlib, random; ..." ในคอมทุกเครื่อง
  • ห้ามย้อนหลัง — เปลี่ยน seed หลังจากสุ่มแล้วทำให้ได้ผลต่างกัน ตรวจจับได้ทันที
{# AUTO_BOOKING #}
AUTO_BOOKING — การจองผ่านระบบปกติ
เมื่อผู้ค้าจองล็อกผ่านหน้า /book ตามปกติ ระบบจะบันทึก ledger ด้วย method=AUTO_BOOKING โดยอัตโนมัติ หลักการคือ "ใครกดก่อนได้ก่อน" ซึ่งเหมาะกับล็อกทั่วไปที่ไม่มีคิวรอ ดัชนีความโปร่งใสจะสูงขึ้นเมื่อตลาดเปลี่ยนไปใช้ SCORING/LOTTERY มากขึ้น
{# Transparency Index #}
ดัชนีความโปร่งใส (Transparency Index) 0–100
index = (ratio_with_reason × 50)
+ (ratio_scoring_lottery × 30)
+ (has_zone_data ? 20 : 0)
  • 50 คะแนน — สัดส่วนการจัดสรรที่มีเหตุผลอ่านออก (reason ไม่ว่าง)
  • 30 คะแนน — สัดส่วน SCORING+LOTTERY เทียบกับทั้งหมด
  • 20 คะแนน — ตลาดมีข้อมูลโซนสาธารณะ (ZoneData)
ตลาดใหม่ที่ยังไม่มีข้อมูลจะได้ 50 คะแนน (default midpoint) จนกว่าจะมีการจัดสรรครั้งแรก
